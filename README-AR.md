# منجز Ultra — المرحلة الثانية (تجهيز حماية XP)

## محتويات الحزمة
- `index.html`: نسخة معدلة لتطلب مكافأة XP من Cloud Function للحسابات المسجلة، وتقرأ XP/Level الموثوقين قبل مزامنة بقية الحالة.
- `functions/index.js`: دالتان خادميتان: `awardStudyReward` بمكافأة محدودة لكل حدث وحد يومي، و`setDeveloperXp` للتحكم بالمطور من الخادم.
- `functions/package.json`: تبعيات Cloud Functions.
- `firebase.json`: إعداد أولي لنشر الوظائف والقواعد.
- `firestore.rules`: نسخة القواعد الحالية التي راجعناها مع قفل `userStats` أمام الكتابة من العميل. **ليست قواعد إطلاق نهائية** لأن التطبيق يحتوي مسارات أخرى تحتاج مراجعة توافق قبل النشر.

## اختبارات أُجريت محليًا
- `node --check` لسكريبت التطبيق بعد التعديل: نجح.
- `node --check` لملف `functions/index.js`: نجح.
- لم يتم تشغيل Firebase Emulator، ولم يتم نشر شيء إلى مشروع Firebase الحقيقي، ولم يتم اختبار المكالمات الشبكية.

## قبل أي نشر
1. ثبّت Firebase CLI وسجّل الدخول للمشروع الصحيح.
2. جهّز مشروع Firebase Functions بخطة فوترة مناسبة حسب متطلبات Firebase الحالية.
3. اختبر في مشروع تجريبي أولًا، لا في قاعدة البيانات الأساسية.
4. القواعد الحالية في هذه الحزمة لا تزال ترفض بعض مسارات التطبيق (مثل إنشاء/تحديث الفرق وبعض التحديات والإعلانات والاستفسارات)، لذلك لا تنشرها كبديل مباشر قبل إنهاء مراجعة جميع المسارات وإكمال القواعد.
5. `awardStudyReward` يضع حدًا لكل مكافأة وحدًا يوميًا، لكنه لا يثبت بمفرده أن الطالب أكمل المهمة فعلًا؛ الإغلاق الكامل للغش يحتاج ربط المكافأة بسجل مهمة/جلسة خادمي موثوق. لا تعتبر هذه المرحلة وحدها حماية نهائية ضد كل أنواع الغش.
6. عند إطلاق الإنتاج، فعّل Firebase App Check بعد تهيئة مفتاح/مزود App Check في التطبيق ثم غيّر `enforceAppCheck` إلى `true`.
7. لا تنسخ أي مفاتيح Admin SDK أو ملفات service-account إلى HTML أو مستودع عام.

## ملاحظة توافق مهمة
قواعد `firestore.rules` في هذه الحزمة مقصود بها أن تكون نقطة عمل آمنة نسبيًا للجزء الذي أُضيف، وليست قواعد نشر نهائية. أبقِ قواعد المشروع الحية كما هي إلى أن تنتهي مراجعة بقية المجموعات واختبار المحاكي.
